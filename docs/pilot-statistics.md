# Статистика пилота

MVP-06 добавляет закрытый раздел «Статистика». Отчет относится к текущему специалисту и всем его данным за все время. Нет выбора периода, фильтра по дате фактического приема или расчета возвращаемости: приложение хранит операции с купонами, а не полный журнал посещений.

## Определения

| Показатель | Как считается | Особые случаи |
| --- | --- | --- |
| Выдано купонов | Все собственные купоны | Отозванные, истекшие и неиспользованные остаются в знаменателе |
| Купоны с применениями | Уникальные купоны с хотя бы одним неотмененным применением | Многоразовый купон считается один раз |
| Неотмененные применения | Все собственные применения без отмены | Один купон может дать несколько операций |
| Клиенты с купонами | Разные внутренние ID клиентов среди неотмененных применений | Несколько купонов одного клиента дают одного клиента; карточки без применений не входят |
| Первое посещение подтверждено | Разные ID клиентов с неотмененным применением и `first_visit_confirmed=true` | Ручное подтверждение специалиста, включая прежние посещения. Не независимая проверка новых посетителей; не ограничено купонами с `first_visit_required=true` |
| Отмененных применений | Собственные операции с отменой | Показаны отдельно; исключены из остальных результатов |
| Доля использованных купонов | Купоны с неотмененными применениями / все выданные купоны | Числитель — купоны, не операции. Если купонов нет — «—»; иначе процент с точностью до одного знака |

Отзыв и истечение запрещают новые применения, но не отменяют уже состоявшиеся. Поэтому использованный впоследствии отозванный купон остается в результате. Отмена последнего применения убирает купон из числителя, клиента — если у него больше нет неотмененных применений, а подтверждение первого посещения — если не осталось соответствующей операции. Повтор отмены не меняет результат второй раз.

Архив и исправление контактов сохраняют ID, счетчики и историю. Разные карточки одного человека считаются разными клиентами; отчет не устанавливает личность и не объединяет совпадения автоматически. Не нужно заводить новую карточку ради нового имени/телефона. Проверяйте поиск и возможные дубликаты.

## API и согласованность

`GET /api/coupons/statistics` требует действующую сессию. Владелец берется только из нее; query-параметры, включая владельца и период, отклоняются с 400. Только GET, другие методы получают 405 (изменяющие запросы прежде проходят Origin/CSRF). Возвращаются `as_of`, `issued_coupons`, `used_coupons`, `active_redemptions`, `unique_clients`, `first_visit_clients`, `canceled_redemptions`. Нет имен, телефонов, ID клиентов или финансовых полей.

Все агрегаты вычисляются одним SQL statement в одном MVCC-снимке; `as_of` — серверное начало этого statement. Нет кеша, таблиц отчетности или обновления счетчиков при чтении. Отмена и изменение `used_count` уже атомарны в MVP-04. Отчет считает факты по журналу применений, а не суммирует счетчики из страниц поиска. Все результаты ограничены владельцем. Работа ограничена пятью секундами, ошибки БД дают 503 без SQL/секретов.

Статистика разделяет существующий бюджет просмотра/поиска купонов — 120 запросов в минуту на специалиста, общий для экземпляров API. При превышении 429 с `Retry-After: 60`. Ответы `no-store`. Никаких изменяющих публичных endpoint не добавлено.

`POST /api/coupons/search` дополнен полем `usage`: `all` (по умолчанию), `used` (есть неотмененные применения), `unused` (нет). Оно пересекается с номером и общим статусом. Купон, все применения которого отменены, относится к `unused`; это не означает, что его никогда не использовали. Старые клиенты без этого поля получают прежний результат. Пагинация по 50, порядок и ограничение поиска сохранены.

Из статистики можно открыть все купоны либо купоны с применениями. В карточке остается история, включая отмены и исходные ручные подтверждения. Отчет загружается при открытии, возвращении фокуса после паузы и по кнопке. При ошибке прежние числа скрываются; время последней успешной проверки показано по Москве. Пустой результат, сбой и завершение сеанса различаются.

## Проверки и границы

PostgreSQL-тесты проверяют нули, независимых владельцев, многоразовые купоны, несколько клиентов, повторные ручные подтверждения одного клиента, отзыв/истечение после применения, отмену/повтор отмены/последнюю отмену, архив/исправление контактов, сохранение аудита, фильтры, сессию и бюджет. Browser-тест проходит создание и поиск клиента без телефона, процентный купон на первое посещение и фиксированный многоразовый купон, публичную карточку, ручные подтверждения, отзыв, отмены и отчет. Текст и верстка проверяются на desktop/mobile и 320 px.

Новых миграций и зависимостей нет. При откате отчет и новый фильтр станут недоступны, исходные данные останутся. Запуск реального пилота и production-развертывание выполняются отдельно по [инструкции пилота](pilot.md). Мы не рассчитываем визиты без купона, возвращаемость, выручку, стоимость привлечения или экономию в рублях.
