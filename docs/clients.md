# Карточки клиентов

MVP-02: специалист создает, ищет, исправляет, архивирует и восстанавливает собственные карточки в разделе «Карточки клиентов». Имя / ФИО обязательно (1–120 Unicode-символов), телефон необязателен. Пробелы имени нормализуются. Телефон содержит 7–15 цифр, допускает начальный `+`, пробелы, скобки и дефисы; исходное форматирование сохраняется. Добавочные номера пока не поддерживаются.

Перед созданием нужно воспользоваться поиском. В форме показываются возможные совпадения по имени или телефону, включая архив. Совпадения — подсказка: общий номер родственников разрешен. Чтобы сохранить отдельную карточку при совпадении, специалист явно подтверждает выбор. Автоматического объединения и переноса истории нет.

Поиск не зависит от регистра, считает `е`/`ё` одинаковыми; телефон ищется по последовательности цифр без форматирования. Национальные префиксы `8` и `+7` автоматически не заменяются: для поиска можно ввести оставшиеся цифры номера. Пустой поиск показывает последние карточки; страница — 50 записей с кнопкой «Показать еще». Список по умолчанию содержит активные записи; доступны архив и все записи. В форме отображаются первые 50 возможных совпадений.

## API и сохранение

- `POST /api/clients/search`: `{query, phone, state, offset}`, все поля необязательны. Имя и отдельный телефон объединяются по OR для подсказок. `state`: `active` по умолчанию, `archived`, `all`; `offset`: 0–100000. Поисковые контакты передаются в JSON, а не URL.
- `POST /api/clients`: `{name, phone}` и обязательный `Idempotency-Key` в формате UUID. Нормализованное содержимое и ключ привязаны к специалисту. Первый ответ — 201, повтор — 200 с той же карточкой в ее текущем состоянии. Другие данные с тем же ключом — 409. После редактирования или архивирования повтор создания не отменяет изменений. Ключ хранится с карточкой без срока удаления.
- `GET /api/clients/{id}`: карточка и 50 последних событий (создание, изменение, архивирование, восстановление). Время задается БД. События сохраняют владельца и версию; API не дублирует его ID. Прежние контактные значения не копируются в аудит.
- `PUT /api/clients/{id}`: `{name, phone, archived, version}`. Версия защищает от потери параллельных правок; устаревшая версия — 409. Изменение без фактической разницы не увеличивает версию. Архивирование сохраняет постоянный ID и все события. Удаления карточек нет.

Все endpoints требуют действующую сессию. Все POST/PUT, включая поиск, требуют Origin и CSRF. Владельца API берет из сессии; чужая и отсутствующая карточки возвращают одинаковый 404. Неизвестные поля, включая ID владельца и клинические сведения, отклоняются. Ответы не кешируются; тела запросов и контакты не журналируются. Локальная проверка выполняется только на искусственных данных.

При потере ответа на создание форма фиксирует отправленные данные и повторяет тот же ключ. Закрытие формы начинает новую операцию: сначала проверьте поиск, если не уверены в результате. Ключ живет в памяти вкладки и не восстанавливается после ее закрытия. При конфликте изменения нужно заново открыть карточку, чтобы увидеть актуальные контакты.

Миграция 003 добавляет `clients` и `client_events`; примененные 001/002 не меняются. Миграция аддитивная: при откате приложения к предыдущему варианту с логином новые таблицы сохраняются.

Карточка не содержит диагноза, даты рождения, заметок, цены или признака первого посещения. Выдача, поиск и отзыв купонов описаны [отдельно](coupons.md); их применения будут следующим этапом; история изменений карточки не является историей визитов.
