# Выдача и отзыв купонов

MVP-03 добавляет раздел «Купоны»: создание, поиск по короткому номеру, просмотр условий и окончательный отзыв с причиной. Для изменения условий создается новый купон. [Шаблоны](coupon-templates.md) позволяют заполнить условия нового купона; выданный купон независим от шаблона. [Использования и отмены](redemptions.md) реализованы в MVP-04; [публичная страница, QR и печать](public-coupons.md) реализованы в MVP-05.

Выдача из шаблона передает необязательный `template_id`: частный источник, не динамическая связь условий. Сервер атомарно проверяет, что шаблон принадлежит специалисту и активен; архив блокирует новую выдачу, но не повтор уже сохраненной операции. У самостоятельных и старых купонов источник null. Поиск принимает `template_id` вместе с прочими фильтрами; пункт «Созданные купоны» шаблона использует этот фильтр и работает после архива. Публичные ответы источник не раскрывают. Миграция 007 добавляет колонку, составной FK владельца и индекс.

## Правила этого PR

- Процент — от 0,01 до 100,00; фиксированная скидка — рубли с копейками от 0,01 до 9 999 999 999,99 ₽. Не больше двух знаков после запятой; принимаются запятая и точка. API получает строку, БД хранит целое число сотых: двоичные float не используются. Итоговая цена приема не рассчитывается.
- Общий и персональный лимиты независимо задаются положительным числом до 2 147 483 647 или отсутствием ограничения (`null`). Персональный лимит по умолчанию — 1, общий — без ограничения. Есть выбор любых или только первых посещений. Карточка клиента не доказывает первое посещение.
- Текст ограничений необязателен, до 2000 Unicode-символов. Строки сохраняются и показываются полностью. Каталога услуг нет.
- Срок — бессрочно либо последний день действия включительно по Москве, фиксированный UTC+3. Например, 27.11.2026 истекает 27.11.2026 в 21:00 UTC (28.11 в 00:00 МСК). В этот точный момент купон уже истек. Прошедшая дата разрешена для регистрации старого бумажного купона и сразу дает статус «Истек срок».
- Короткий номер — ровно 6 цифр, присваивается только системой криптографически случайно с проверкой уникальности у специалиста. В форме нет ручного ввода, API создания отклоняет поле `code`, даже пустое. При совпадении система выбирает другой номер. Поиск точный: пробелы и дефисы игнорируются, пропущенные ведущие нули восстанавливаются. Номер можно переписать на бумагу после создания. Номера никогда не освобождаются, в том числе после истечения и отзыва.
- Системный ID — случайный UUIDv4. Он используется в публичной ссылке/QR; применение доступно в закрытом кабинете.
- «Кому выдан» (в интерфейсе «Кто передаст купон») — необязательный собственный активный клиент, который может передать купон близкому. Это рекомендатель, а не клиент, применивший скидку; привязка не ограничивает получателя. Архивирование или исправление контактов этого клиента сохраняет связь. В кабинете показывается текущее имя клиента.

Выбранные детали выше фиксируются как решения MVP-03 и явно отражены в форме; прежняя спецификация оставляла их открытыми.

## Сохранение и отзыв

Создание требует `Idempotency-Key` UUID, принадлежащий операции. Повтор нормализованного запроса с тем же ключом возвращает ту же запись в актуальном состоянии. Измененные данные с тем же ключом возвращают 409 `conflict`. Сетевой сбой не требует новой выдачи: форма повторяет сохраненные данные и ключ. После явного закрытия/перезагрузки вкладки сначала проверьте поиск, поскольку ключ хранится в памяти вкладки. Ошибка валидации позволяет исправить поля. Номер не входит в содержимое запроса создания и назначается сервером один раз.

Отзыв требует причины (1–500 Unicode-символов). Он окончателен и записывает автора, время и причину вместе с изменением купона в одной транзакции. Повтор и конкурентные отзывы оставляют одну запись, первое время и первую причину. Повтор создания после отзыва возвращает отозванную запись. Удаления, переиспользования номера и скрытого восстановления нет.

Состояния: отозван → истек срок → исчерпан общий лимит → доступен. Это общий статус; условия конкретного клиента проверяются при подтверждении использования. Счетчик отражает подтвержденные неотмененные операции; поиск и просмотр его не меняют.

## Доступ и API

- `POST /api/coupons` — выдать; 201 для нового купона и 200 при повторе.
- `POST /api/coupons/search` — точный номер, фильтр состояния, `usage` (`all`, `used`, `unused` по неотмененным применениям), `offset`; 50 записей, newest first, без общего count. Пустой номер показывает все собственные записи.
- `GET /api/coupons/{id}` — условия и события создания/отзыва.
- `POST /api/coupons/{id}/revoke` — окончательный отзыв с `{reason}`.

Точный контракт и значения по умолчанию — в [OpenAPI](../api/openapi.yaml). Сессия обязательна везде, для POST требуются Origin и CSRF. Владелец берется только из сессии; чужая и отсутствующая запись дают одинаковый 404. Клиент другого специалиста не может стать рекомендателем. Неизвестные поля отклоняются. Ответы no-store; тела, контакты, токены и параметры БД не журналируются.

`GET /api/coupons/statistics` возвращает собственные агрегаты пилота; см. [определения](pilot-statistics.md). Поиск, просмотр и статистика делят бюджет 120 запросов в минуту на специалиста в PostgreSQL, общий для всех экземпляров API. При превышении — 429 `too_many_requests`, `Retry-After: 60`. Перезапуск API и поддельный X-Forwarded-For не сбрасывают бюджет. Неудачные попытки поиска тоже считаются. Другие специалисты имеют независимые бюджеты.

Миграция 004 аддитивно добавляет купоны, аудит и бюджеты поиска, а также индекс владельца/ID клиента для составного внешнего ключа. Старые миграции не меняются. При откате приложения к версии карточек клиентов новые таблицы сохраняются. Запуск — `make up`, явное создание специалиста — `make create-user`.

Проверки используют искусственные данные: точные десятичные значения и граница дня, выдача/повтор/запрет ручного номера, собственность/CSRF, независимые лимиты, конкурентные отзывы и бюджеты поиска, browser-сценарии desktop/mobile и потерянный ответ создания. Реальные клиентские данные для разработки не нужны.
