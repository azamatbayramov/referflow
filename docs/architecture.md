# Архитектура

## Текущий объем

Referflow начинается с модульного монолита: один Go-процесс, одна PostgreSQL и статическое Vue-приложение. Реализован вход специалиста: таблицы учетных записей, сессий и ограничений попыток входа, явные SQL-миграции, экран входа и кабинет с профилем. Клиенты и купоны пока не реализованы.

Планируемый учет клиентов, купонов и их применений описан в [спецификации MVP](coupon-mvp.md); последовательность реализации — в [плане работ](mvp-backlog.md). В первой версии нет журнала визитов, Google Sheets и других CRM-интеграций. Первое посещение и правило одного купона на визит подтверждает специалист; система автоматически проверяет срок, отзыв и лимиты применений. Эти документы не меняют текущий статус инфраструктурного каркаса.

Выбран Go с `net/http`: маршрутизация, JSON, проверка пароля и защита сессий используют стандартную библиотеку. pgx отвечает за пул PostgreSQL. Vue + Vite дает независимую сборку интерфейса без отдельного Node.js-процесса на production-сервере. SSR, очередь, кеш, ORM и глобальное хранилище состояния сейчас не нужны.

## Границы

| Компонент | Ответственность | Не входит в ответственность |
| --- | --- | --- |
| Caddy | HTTPS, статические файлы, проксирование `/api` | Бизнес-правила и доступ к БД |
| Vue | Вход/выход и представление данных своей сессии | Секреты и прямой доступ к БД |
| Go API | HTTP, авторизация, сессии, конфигурация и пул БД | Выпуск TLS-сертификатов и сборка UI |
| PostgreSQL | Постоянное хранение | Самостоятельная реализация бизнес-процессов |

Браузер обращается к одному origin. Caddy передает `/api` и `/api/*` в `api:8080`, сохраняя префикс. Остальные пути обслуживаются из сборки Vue с fallback на `index.html`. Неизвестные API-пути и отсутствующие файлы `/assets/*` возвращают 404, а не HTML с кодом 200. При разработке эту функцию прокси выполняет Vite.

## Жизненный цикл API

1. Прочитать и проверить переменные окружения. Пароль обязателен; конфигурация не выводится в логи.
2. Создать небольшой пул PostgreSQL и начать слушать HTTP. Соединение устанавливается при обращении к пулу.
3. `/api/healthz` проверяет процесс, `/api/readyz` проверяет примененные миграции и их контрольные суммы с ограничением в две секунды.
4. При SIGTERM/SIGINT остановить прием новых запросов, дать активным до десяти секунд и закрыть пул.

Без примененных миграций readiness возвращает 503. Миграции выполняются командой `manage migrate` до запуска новой версии; API не меняет схему при старте. Compose health check использует readiness; статус `unhealthy` сам по себе не перезапускает контейнер. `restart: unless-stopped` в production реагирует на завершение процесса.

## Как расширять

- Первую функцию добавлять целиком: контракт, обработчик, бизнес-правило, SQL/миграция при необходимости, интерфейс и проверки.
- Выделять пакеты по конкретным функциям. Не создавать заранее набор пустых `service`, `repository` и `domain` абстракций.
- Общий HTTP-контракт находится в `api/openapi.yaml`. Генератор клиентского SDK добавляется, когда фронтенд начнет вызывать бизнес-API.
- Для закрытых операций получать владельца из проверенной серверной сессии. Текущие health endpoints публичны и не раскрывают подробности подключения. Подробнее — [авторизация](authentication.md).
- Вход и кабинет используют состояние Vue на одном URL; отдельных маршрутов, UI kit и глобального store пока не требуется. При добавлении новых разделов выбрать маршрутизацию по реальной потребности.

Базовые материалы: [Go net/http](https://pkg.go.dev/net/http), [Vue](https://vuejs.org/guide/introduction.html), [Vite](https://vite.dev/guide/), [Caddy](https://caddyserver.com/docs/caddyfile), [Compose](https://docs.docker.com/compose/).
