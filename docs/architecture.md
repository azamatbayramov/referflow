# Архитектура

## Текущий объем

Referflow начинается с модульного монолита: один Go-процесс, одна PostgreSQL и статическое Vue-приложение. Предметная область пока не реализована. В базе нет прикладных таблиц; веб-страница сообщает о подготовке к запуску.

Планируемое поведение купонов и ручной учет клиентов/визитов описаны в [спецификации MVP](coupon-mvp.md); последовательность реализации — в [плане работ](mvp-backlog.md). Первая версия работает без Google Sheets и других CRM-интеграций. Эти документы не меняют текущий статус инфраструктурного каркаса.

Выбран Go с `net/http`: для двух инфраструктурных endpoints достаточно стандартной библиотеки. pgx отвечает за пул PostgreSQL. Vue + Vite дает независимую сборку интерфейса без отдельного Node.js-процесса на production-сервере. SSR, очередь, кеш, ORM и глобальное хранилище состояния сейчас не нужны.

## Границы

| Компонент | Ответственность | Не входит в ответственность |
| --- | --- | --- |
| Caddy | HTTPS, статические файлы, проксирование `/api` | Бизнес-правила и доступ к БД |
| Vue | Представление и будущие пользовательские сценарии | Секреты и прямой доступ к БД |
| Go API | HTTP, жизненный цикл, конфигурация, пул БД | Выпуск TLS-сертификатов и сборка UI |
| PostgreSQL | Постоянное хранение | Самостоятельная реализация бизнес-процессов |

Браузер обращается к одному origin. Caddy передает `/api` и `/api/*` в `api:8080`, сохраняя префикс. Остальные пути обслуживаются из сборки Vue с fallback на `index.html`. Неизвестные API-пути и отсутствующие файлы `/assets/*` возвращают 404, а не HTML с кодом 200. При разработке эту функцию прокси выполняет Vite.

## Жизненный цикл API

1. Прочитать и проверить переменные окружения. Пароль обязателен; конфигурация не выводится в логи.
2. Создать небольшой пул PostgreSQL и начать слушать HTTP. Соединение устанавливается при обращении к пулу.
3. `/api/healthz` проверяет процесс, `/api/readyz` делает `Ping` с ограничением в две секунды.
4. При SIGTERM/SIGINT остановить прием новых запросов, дать активным до десяти секунд и закрыть пул.

Readiness не проверяет миграции: схемы пока нет. Когда появятся миграции, критерии готовности нужно расширить вместе с функцией, которой нужна схема. Compose health check использует readiness; статус `unhealthy` сам по себе не перезапускает контейнер. `restart: unless-stopped` в production реагирует на завершение процесса.

## Как расширять

- Первую функцию добавлять целиком: контракт, обработчик, бизнес-правило, SQL/миграция при необходимости, интерфейс и проверки.
- Выделять пакеты по конкретным функциям. Не создавать заранее набор пустых `service`, `repository` и `domain` абстракций.
- Общий HTTP-контракт находится в `api/openapi.yaml`. Генератор клиентского SDK добавляется, когда фронтенд начнет вызывать бизнес-API.
- До появления закрытых операций добавить аутентификацию и авторизацию. Текущие health endpoints публичны и не раскрывают подробности подключения.
- UI kit и router выбрать с первым реальным экраном, чтобы решение опиралось на требования.

Базовые материалы: [Go net/http](https://pkg.go.dev/net/http), [Vue](https://vuejs.org/guide/introduction.html), [Vite](https://vite.dev/guide/), [Caddy](https://caddyserver.com/docs/caddyfile), [Compose](https://docs.docker.com/compose/).
