# Шаблоны купонов

Раздел «Шаблоны» сохраняет повторяющиеся условия специалиста. В шаблоне есть обязательное частное название (1–120 Unicode-символов), вид и номинал скидки, текст ограничений, общий/персональный лимиты, первое/любое посещение и необязательная дата окончания. Названия могут совпадать. Правила точности, лимитов и дат совпадают с [купонами](coupons.md); персональный лимит по умолчанию 1, общий — без ограничения.

## Работа в кабинете

1. В разделе «Шаблоны» нажмите «Создать шаблон», задайте название/условия и сохраните. После создания название и условия неизменяемы: для других условий создайте новый шаблон. Поиск по части названия запускается через 300 мс после ввода, без учета регистра, с эквивалентностью е/ё. По умолчанию архив скрыт и из списка, и из поиска; флажок «Показывать архивированные» включает его. Страницы по 50.
2. Карточка показывает скидку, ограничения, лимиты и срок. Нижняя кнопка «Выдать по шаблону» перечитывает запись и открывает обычную форму выдачи. В форме доступны три наиболее используемых активных шаблона (по числу связанных выданных купонов, при равенстве — новые) и «Больше шаблонов». Условия можно изменить для одного купона; выдача требует отдельного нажатия «Выдать купон». Избранного пока нет.
3. Меню «⋯» справа вверху предлагает «В архив»/«Восстановить» с отдельным подтверждением и «Созданные купоны» — список, отфильтрованный по исходному шаблону. Архив/восстановление не меняет уже выданные купоны.

Шаблон — набор значений для копирования. У него нет номера, публичной страницы, QR, рекомендателя, клиента-получателя или счетчиков. Каждый выданный купон получает новый шестизначный номер, UUIDv4, независимые общий/персональный лимиты, счетчики и историю. Лимит шаблона задает лимит **каждого** нового купона, а не общий бюджет всех выданных копий. Шаблоны не входят в статистику выданных купонов.

Дата окончания **абсолютная**, последний день включительно по Москве (UTC+3), либо бессрочно. Она копируется без продления при выдаче: старый срок дает истекший купон, что явно показано в форме. Срок «N дней с выдачи» не вводится. Купон сохраняет частный `template_id` как источник; условия остаются независимым снимком. Архив исходного шаблона не переписывает черновик, но блокирует новую выдачу из него: выберите другой источник или начните самостоятельный купон. Повтор уже сохраненной выдачи работает и после архива. Рекомендатель выбирается заново только в купоне. Ручные подтверждения использования по-прежнему исходно сняты.

Название и ID шаблона видны только специалисту; в публичный API, QR, PNG и печать они не передаются. Свободный текст ограничений станет публичным условием купона — не добавляйте в него данные клиентов. Программ лояльности, кампаний, учета визитов и CRM-интеграций нет.

## Сохранение, конкуренция и доступ

- `POST /api/coupons/templates` — создать (201), повтор (200).
- `POST /api/coupons/templates/search` — поиск собственных записей; `sort: popular` сортирует по числу выданных купонов, по умолчанию — новые сначала.
- `GET /api/coupons/templates/{id}` — актуальная собственная запись.
- `PUT /api/coupons/templates/{id}` — архив/восстановление с ожидаемой `version` (200). Название и условия нужно передать без изменений; попытка их изменить дает 400.

Создание и изменение требуют отдельного `Idempotency-Key` UUID. Успешная операция и постоянный ключ/хеш сохраняются одной транзакцией. Повтор того же нормализованного содержимого, пути и ключа возвращает текущую запись, даже после более поздних изменений; он не восстанавливает старые условия и не отменяет архив. Другие данные с сохраненным ключом дают 409. Параллельные новые изменения одной версии дают ровно одно успешное сохранение; второе получает 409 без перезаписи.

При неизвестном результате поля/ключ замораживаются; повтор отправляет тот же запрос. Переключение разделов не уничтожает форму; сеанс/перезагрузка уничтожают ее, после чего сначала нужна сверка списка. Известный конфликт требует загрузить актуальную версию и заново выбрать архивное действие. Новые действия с купоном не заменяют незавершенную отправку уже открытого купона.

Владелец только из сессии, чужая/отсутствующая запись одинаково дает 404. Все изменения и поиск защищены Origin/CSRF, все ответы no-store. Код, UUID купона, клиентские привязки, ID специалиста и неизвестные поля в теле отклоняются. Чтение и поиск делят существующий бюджет купонов 120 запросов в минуту на специалиста; превышение — 429 с Retry-After: 60. [OpenAPI](../api/openapi.yaml) описывает поля и ошибки.

## Схема и проверки

Миграция 006 добавляет `coupon_templates` и `coupon_template_operations`. Миграция 007 добавляет nullable `coupons.template_id`, составной FK владельца и индекс выборки по источнику. У старых купонов источник неизвестен и остается null. FK хранит происхождение, а не динамические условия. Старые миграции не меняются. Применяйте миграции отдельным `manage migrate` до запуска новой API (`make up` делает это). При откате приложения данные сохраняются. CI backup/restore проверяет искусственные данные во всех 12 таблицах, включая шаблон и постоянный ключ его операции.

Проверки: общая валидация условий и названия, неизменяемость, изоляция, CSRF/неизвестные поля, конкурентное создание/архивирование, повторы после изменения статуса, архив/восстановление, пагинация, популярность, бюджет чтения, независимость и источник купонов. Browser-сценарии на телефоне и компьютере проверяют полный цикл, изменение одной копии, приватность источника, потерянные ответы создания/архива, переходы между разделами, конфликт версий и перепроверку архива перед выдачей.
