# Шаблоны купонов

Раздел «Шаблоны» сохраняет повторяющиеся условия специалиста. В шаблоне есть обязательное частное название (1–120 Unicode-символов), вид и номинал скидки, текст ограничений, общий/персональный лимиты, первое/любое посещение и необязательная дата окончания. Названия могут совпадать. Правила точности, лимитов и дат совпадают с [купонами](coupons.md); персональный лимит по умолчанию 1, общий — без ограничения.

## Работа в кабинете

1. В разделе «Шаблоны» нажмите «Создать шаблон», задайте название/условия и сохраните. Поиск работает по части названия без учета регистра, с эквивалентностью е/ё. Есть фильтр активных, архивных и всех записей и страницы по 50.
2. «Выдать по шаблону» перечитывает актуальную запись и открывает обычную форму выдачи. Также в форме выдачи есть переход «Заполнить из шаблона». Условия можно проверить и изменить для одного купона; сама выдача требует отдельного нажатия «Выдать купон».
3. Изменение/архив/восстановление шаблона не меняет выданные купоны. В редакторе отметка «Убрать шаблон в архив» сохраняется вместе с остальными изменениями; снятие отметки восстанавливает шаблон. Архивные шаблоны не предлагаются для выдачи, но сохраняются в кабинете.

Шаблон — набор значений для копирования. У него нет номера, публичной страницы, QR, рекомендателя, клиента-получателя или счетчиков. Каждый выданный купон получает новый шестизначный номер, UUIDv4, независимые общий/персональный лимиты, счетчики и историю. Лимит шаблона задает лимит **каждого** нового купона, а не общий бюджет всех выданных копий. Шаблоны не входят в статистику выданных купонов.

Дата окончания **абсолютная**, последний день включительно по Москве (UTC+3), либо бессрочно. Она копируется без продления при выдаче: старый срок дает истекший купон, что явно показано в форме. Срок «N дней с выдачи» не вводится. Уже заполненный черновик самостоятельный: последующие правки или архив исходного шаблона его не переписывают. Рекомендатель выбирается заново только в купоне. Ручные подтверждения использования по-прежнему исходно сняты.

Название шаблона видно только специалисту; в публичный API, QR, PNG и печать оно не передается. Свободный текст ограничений станет публичным условием купона — не добавляйте в него данные клиентов. Программ лояльности, кампаний, учета визитов и CRM-интеграций нет.

## Сохранение, конкуренция и доступ

- `POST /api/coupons/templates` — создать (201), повтор (200).
- `POST /api/coupons/templates/search` — поиск собственных записей.
- `GET /api/coupons/templates/{id}` — актуальная собственная запись.
- `PUT /api/coupons/templates/{id}` — полностью сохранить название, условия и архивный статус с ожидаемой `version` (200).

Создание и изменение требуют отдельного `Idempotency-Key` UUID. Успешная операция и постоянный ключ/хеш сохраняются одной транзакцией. Повтор того же нормализованного содержимого, пути и ключа возвращает текущую запись, даже после более поздних изменений; он не восстанавливает старые условия и не отменяет архив. Другие данные с сохраненным ключом дают 409. Параллельные новые изменения одной версии дают ровно одно успешное сохранение; второе получает 409 без перезаписи.

При неизвестном результате поля/ключ замораживаются; повтор отправляет тот же запрос. Переключение разделов не уничтожает форму; сеанс/перезагрузка уничтожают ее, после чего сначала нужна сверка списка. Известный конфликт требует загрузить актуальную версию и заново внести правки. Новые действия с купоном не заменяют незавершенную отправку уже открытого купона.

Владелец только из сессии, чужая/отсутствующая запись одинаково дает 404. Все изменения и поиск защищены Origin/CSRF, все ответы no-store. Код, UUID купона, клиентские привязки, ID специалиста и неизвестные поля в теле отклоняются. Чтение и поиск делят существующий бюджет купонов 120 запросов в минуту на специалиста; превышение — 429 с Retry-After: 60. [OpenAPI](../api/openapi.yaml) описывает поля и ошибки.

## Схема и проверки

Миграция 006 аддитивно добавляет `coupon_templates` и `coupon_template_operations` с составным FK владельца. Старые миграции и таблицы купонов не меняются; шаблон не связан динамическим FK с купоном. Применяйте миграцию отдельным `manage migrate` до запуска новой API (`make up` делает это). При откате приложения таблицы сохраняются. CI backup/restore проверяет искусственные данные во всех 12 таблицах, включая шаблон и постоянный ключ его операции.

Проверки: общая валидация условий и названия, изоляция, CSRF/неизвестные поля, конкурентное создание/редактирование, повторы после дальнейшего изменения, архив/восстановление, пагинация, бюджет чтения, независимость выданных купонов. Browser-сценарии на телефоне и компьютере проверяют полный цикл, изменение одной копии, приватность названия, потерянные ответы создания/изменения, переходы между разделами, конфликт версий и перепроверку архива перед выдачей.
