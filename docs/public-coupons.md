# Публичная и печатная карточка купона

MVP-05 добавляет одну карточку для ссылки, QR, PNG и бумаги. В кабинете откройте купон и выберите вкладку «Отправить»: здесь видны QR, копирование ссылки и сохранение изображения. Нажмите «Открыть карточку для клиента» для публичного представления. В публичной карточке кнопка «Сохранить купон» скачивает PNG; печать и обновление статуса находятся в «Печать и проверка». Доступна печать (в том числе в PDF средствами браузера). Карточка доступна без входа и установки приложения.

## Ссылка и публичные данные

Документ `/c/{uuid}` использует существующий криптографически случайный UUIDv4 купона. Короткий номер остается шестизначным, назначается только сервером и используется для закрытого поиска специалистом. Публичного поиска по номеру, списка купонов или выбора владельца нет. Номера уникальны у специалиста; UUID уникален глобально. UUID не печатается строкой: он находится внутри ссылки/QR.

`GET /api/public/coupons/{uuid}` (также HEAD) возвращает только десять публичных полей: `code`, `discount_type`, `value`, `restrictions`, `total_limit`, `per_client_limit`, `first_visit_only`, `expires_on`, `expires_at`, `status`. Ответ формируется отдельным SQL-запросом и DTO без соединения с клиентами/сессиями. ФИО, телефон, ID клиента/владельца/операции, рекомендатель, логин специалиста, история, число использований и причины отзыва/отмены не возвращаются. Состояние учитывает счетчик без раскрытия его значения.

Публичный UUID дает возможность прочитать условия, а не изменить купон. Неверный формат, несуществующий UUID и короткий номер дают одинаковый 404 `not_found`. Изменяющие методы получают 405 `method_not_allowed`; доступ к закрытым API по-прежнему требует сессии, владельца и для POST — Origin/CSRF. Чтение ограничено двумя секундами; при сбое хранилища — 503 без подробностей. Сканирование, чтение, копирование, скачивание и печать не записывают события, не резервируют и не расходуют использования.

Ссылка передаваемая: ее обладатель может прочитать условия. UUID не заменяет авторизацию, а ограничивает угадывание. Поля условий и ограничений становятся публичными; не указывайте в них данные клиентов. Заголовок `noindex` ограничивает индексацию, но не является контролем доступа.

## Актуальность и доступность

Порядок общего статуса: отозван → истек срок → исчерпан общий лимит → доступен. Персональный лимит и первое посещение нельзя проверить для анонимного зрителя. Карточка явно говорит, что условия для клиента и актуальность проверит специалист перед применением. Просмотр, копия или QR не гарантируют и не резервируют скидку. Отмена использования может вернуть общий статус «Доступен», но не отменяет отзыв/истечение.

HTML документа и JSON имеют `Cache-Control: no-store`. Документ и API получают `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow, noarchive`. Meta referrer действует и при Vite-разработке. В публичной ветке frontend не запрашивает сессию; публичный fetch использует `credentials: omit`, `cache: no-store`. Нет аналитики, внешних шрифтов, генератора QR или image-сервиса, которым мог бы передаваться UUID.

Каждое открытие/перезагрузка проверяет сервер. Открытая видимая страница обновляется раз в минуту, на границе срока и при возвращении из другой вкладки/истории браузера. Есть явная кнопка «Обновить статус». Перед PNG/печатью статус запрашивается заново. При сетевом сбое прежняя карточка скрывается: нельзя скачать/распечатать ее с устаревшим статусом «Доступен». Изменение статуса после проверки все равно возможно; проверка при применении на сервере остается окончательной.

## Бумага и изображение

Карточка показывает короткий номер, точный номинал, срок включительно по Москве либо бессрочность, оба независимых лимита, первое/любые посещения, один купон на прием и полный текст ограничений. Переносы строк сохраняются; длинные слова переносятся. UUID/URL не занимают строку на бумаге, в PNG их представляет QR. Бумажный бланк можно заполнить от руки по этой записи; копии используют те же серверные лимиты.

Печатные стили скрывают навигацию и кнопки, используют A5 и читаемый черно-белый QR. Очень длинные ограничения увеличивают карточку и могут продолжаться на следующих листах, а не обрезаются ради фиксированного размера. При ручной настройке печати отключите колонтитулы браузера, если они добавляют адрес страницы. PNG включает все условия, момент проверки, предупреждение об актуальности и тот же QR. Сохраненное изображение/бумага — снимок; по QR всегда открывается текущая запись.

QR генерируется локально библиотекой `qrcode-generator` 2.0.4 (MIT, без транзитивных зависимостей): автоматический размер, коррекция M, четыре пустых модуля вокруг. Библиотека добавлена вместо собственной реализации кодирования. Для browser-проверки реального считывания SVG/PNG используется только dev-зависимость `jsqr` 1.4.0. SVG помещается в `<img>` как data URL, без `v-html`; ограничения выводятся обычным текстом. URL составляется из origin открытого приложения и `/c/{uuid}`, без query/hash и пользовательского текста. Для рассылки вне своего устройства открывайте кабинет по доступному клиентам production-домену; `localhost` ведет на устройство получателя, а не на сервер.

Публичная карточка не добавляла визитов, интеграций или таблиц. [Шаблоны купонов](coupon-templates.md) реализованы отдельно, их частное название не входит в публичные данные. Для самой публичной карточки миграции не требуются: уже выданные купоны получают публичную карточку с тем же UUID. При откате frontend/API публичные ссылки перестанут работать, данные купонов и применений сохранятся. Production-развертывание — отдельная операция.

## Проверки

Backend: публичный allowlist, отсутствие приватных данных даже с неверной cookie/поддельным query, только UUIDv4, read-only методы, повторные/конкурентные просмотры без событий/расхода, переходы доступен → исчерпан → отменен → доступен → истек → отозван, ошибка хранилища. Прежние проверки изоляции и CSRF остаются обязательными.

Browser desktop/mobile: анонимный прямой URL, QR декодируется в исходную ссылку, PNG скачивается и его QR также декодируется, печатные стили/PDF, длинные многострочные ограничения и ширина 320 px, отзыв/отмена/ошибка связи/404, ссылка из кабинета. Полный Compose/Caddy проверяет headers, API-прокси и fallback для `/c/…` без подмены ошибок API на HTML. Данные тестов искусственные.
